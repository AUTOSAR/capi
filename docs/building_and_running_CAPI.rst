Building and Running CAPI
=========================

1 Build Environment Setup
-------------------------

If you use the devcontainer (see .devcontainer folder) you can skip to step 2 of this section.

1.1 Installing Software Dependencies
************************************

**Requirements**

- Ubuntu 20.04
- Python 3.8

**Install system packages**

.. code-block:: bash

   sudo apt install -y \
       build-essential pkg-config cmake make patch tar sed git \
       gperf autoconf libtool pigz python3-pip

**Install Python packages**

.. code-block:: bash

   pip install gitpython json5 jsonpath pyelftools Jinja2 lxml xmltodict pyinstaller psutil

**Tested package versions**

- gitpython 3.1.50
- json5 0.14.0
- jsonpath 0.82.2
- pyelftools 0.32
- Jinja2 3.1.6
- lxml 4.9.1
- xmltodict 0.14.2
- pyinstaller 6.21.0
- psutil 7.2.2


1.2 Configuring Directory Structure
***********************************

For ease of subsequent operations, we pre-define some configurations. Users can modify them according to their actual situation or preferences:

.. code-block:: bash

    # CAPI source code directory
    export CAPI_SRC_DIR="/workspaces/capi"
    # SDK-UTILS directory
    export SDK_UTILS="${CAPI_SRC_DIR}/isoft/sdk-utils/bin/sdk-utils.py"
    # CAPI build directory, used to store temporary files during compilation
    export CAPI_BUILD_DIR="${CAPI_SRC_DIR}/build"
    # CAPI_SDK directory, used to store generated SDK files
    export SDK_OUTPUT_DIR="${CAPI_SRC_DIR}/build/sdk"
    # SDK_INST directory, used to store installed SDK
    export SDK_INST_DIR="${HOME}/capi/sdk-native"
    # ARA_SYSROOT directory
    export ARA_SYSROOT="${HOME}/capi/ara-sysroot"

The above code can be directly copied to the command line for execution, facilitating subsequent operations.

2  Build Steps
--------------

The CAPI source code directory includes a built-in SDK build tool called ``sdk-utils``, which can be used to compile CAPI source code and generate SDK files.

During the compilation of CAPI source code, sdk-utils will automatically download, compile, and install all dependencies of CAPI.

.. code-block:: bash

    # Compile CAPI source code
    ${SDK_UTILS} build -o "${CAPI_BUILD_DIR}" -v "2608" "apall#${CAPI_SRC_DIR}"
    # Pack and generate SDK
    ${SDK_UTILS} pack -o "${SDK_OUTPUT_DIR}" "${CAPI_BUILD_DIR}"

After the above operations are completed, an SDK file named for example ``SDK-1.0.0.2608-x86_64-ubuntu20.04-native-Debug.run`` will be generated in the ``${SDK_OUTPUT_DIR}`` directory.


Using SDK
==========

1 Installation
--------------

The SDK generated by CAPI compilation is an executable self-extracting file that can be directly used for installation.

Run the SDK file on the command line and specify an installation directory (which will be created automatically):

.. code-block:: bash

    ${SDK_OUTPUT_DIR}/SDK-*.run ${SDK_INST_DIR}

2 Building Applications
-----------------------

2.1 Example Program Overview
*****************************

For the examples in this document a demo application is used.
You can find more information about the demo in `docs/tutorials/demo.rst <docs/tutorials/demo.rst>`_.


2.2 Compile & Install AA (Adaptive Application)
***********************************************

The SDK includes a built-in script named build.sh, which can be used to compile and install Adaptive Applications.

Execute the compilation and installation of the desired AA on all desired machines respectively:

.. code-block:: bash

    # As an example, the source directory of the demo is shown here.
    AA_SRC_FOLDER="${CAPI_SRC_DIR}/samples/helloworld-cm" \
    ${SDK_INST_DIR}/ara-sysroot/build.sh -i ${AA_SRC_FOLDER}


2.3 Configure Machines
**********************

The SDK includes a built-in script named config.sh, which can be used to configure the target machines.

Execute the following operation on each machine:

.. code-block:: bash

    # As an example, the command for the demo Machine1 is shown here.
    MACHINE_NAME="Machine1" \
    AA_SRC_FOLDER="${CAPI_SRC_DIR}/samples/helloworld-cm" \
    MACHINE_IP="192.168.1.100" # just an example value \
    ${SDK_INST_DIR}/ara-sysroot/config.sh -m ${MACHINE_NAME} -s ${ARA_SYSROOT} -a ${AA_SRC_FOLDER} -p ${MACHINE_IP}


2.4 Running AA
**************

The SDK includes a built-in script named run.sh, which can be used to start/stop machines and switch function groups.

- To observe the runtime behavior, download `dlt-viewer <https://github.com/COVESA/dlt-viewer/releases/tag/2.30.0>`__ and configure the ECUs with the actual IP addresses of the machines you start.

- Start the program and execute on the machines where the adaptive applications are located:

.. code-block:: bash

    # 1. Start machine
    # Execute the following command(s) in the same terminal as the previous step(s).
    sudo ${ARA_SYSROOT}/run.sh -R
    # 2. Start application (switch the associated function group to a state where the application is active)
    # Open a new terminal and run the following command(s).
    # As an example, the function group state to start the demo is shown here.
    ARA_SYSROOT="${HOME}/capi/ara-sysroot" \
    FUNCTION_GROUP="HelloWorldGroup" \
    NEW_STATE="Driving" \
    sudo ${ARA_SYSROOT}/run.sh -c ${FUNCTION_GROUP}.${NEW_STATE}

- Search for CAPI in dlt-viewer to see related logs.

- To stop a machine execute on it:

.. code-block:: bash

    sudo ${ARA_SYSROOT}/run.sh -s
